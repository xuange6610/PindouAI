# 技术架构与源码运行

PindouAI 采用“离线优先 Flutter 客户端 + 可选服务端”结构。核心图片算法和本地数据管理在客户端完成，FastAPI 与 AI 工作台只有在需要云能力时才启动。

## 主要目录

| 目录 | 作用 |
| --- | --- |
| `lib/` | Flutter 应用、页面、算法和本地服务 |
| `test/` | Flutter 单元与组件测试 |
| `assets/` | 字体、完整图纸预览和运行资源 |
| `android/`、`windows/` | 平台工程和打包配置 |
| `backend/` | 可选 FastAPI 服务 |
| `ai-platform/` | 可选 Vue/FastAPI AI 工作台 |
| `docs/` | 架构、测试报告和 GitHub Pages |
| `tool/` | 图集和开发辅助脚本 |

## 客户端流程

`导入 → 方向校正与裁切 → 目标格数缩放 → LAB 聚类 → CIEDE2000 色差匹配 → 品牌色号 → PNG/PDF/清单`

算法任务通过 Flutter 后台执行能力避免长时间阻塞界面。200×200 画板最多包含 40,000 格，因此大尺寸与多颜色会明显增加计算和导出成本。

## 获取源码

```bash
git lfs install
git clone https://github.com/xuange6610/PindouAI.git
cd PindouAI
flutter pub get
```

仓库的大型图纸资源通过 Git LFS 管理。只下载 Git 源文件而没有拉取 LFS 对象时，应用无法获得完整图库。

## 运行和检查

```bash
flutter analyze
flutter test
flutter run -d android
flutter run -d windows
```

Windows 构建需要 Visual Studio 的 Desktop development with C++ 工作负载；Android 需要 Android SDK、模拟器或真机。

## 可选服务

```bash
docker compose -f backend/docker-compose.yml up --build
docker compose -f ai-platform/docker-compose.yml up --build
```

复制对应 `.env.example` 后在本机创建 `.env`。真实密钥、数据库密码、签名 keystore 和私钥不得提交到 Git。

## 架构边界

- 基础制图不依赖后端。
- 本地模式不会自动上传用户照片。
- 云模式必须由用户主动配置地址和凭据。
- iOS 有平台源码，但当前公开 Release 只交付 Android 和 Windows 成品。
